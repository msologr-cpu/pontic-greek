# Задание: подать Pontic Greek в официальный каталог Keyman

## Контекст

У нас есть рабочий пакет клавиатуры Keyman: `keyman/source/pontic_greek.kmn`
(+ .kps, .js, welcome.htm, встроенный шрифт PonticSans-Regular.ttf). Он уже
собирается и работает — им пользуются на Android и iOS через прямую загрузку
`.kmp`. Сейчас клавиатуру можно поставить только скачав файл вручную.

Цель — подать её в официальный репозиторий `keymanapp/keyboards`, чтобы она
появилась в каталоге Keyman и ставилась в один клик прямо из приложения
Keyman на **всех** платформах, которые оно поддерживает (Android, iOS,
Windows, macOS, Linux, web) — без поиска файла на GitHub.

Репозиторий: https://github.com/msologr-cpu/pontic-greek (наш, публичный)
Целевой репозиторий: https://github.com/keymanapp/keyboards (форкнуть, PR)

## Что сделать по шагам

### 1. Разобраться в требованиях официального репозитория

- Прочитать README и всё, на что оно ссылается:
  https://github.com/keymanapp/keyboards
  https://help.keyman.com/developer/keyboards/
  — там есть «GitHub Keyboard Submission Guide» и «Keyboard Design Principles
  (D.I.S.C.U.S.)» — обязательно прочитать оба перед началом.
- Понять структуру: `release/` (полный набор + прошло проверку качества),
  `experimental/` (в разработке), `legacy/` (старые бинарные). Нам нужен
  `release/`, но реалистичнее начать с `experimental/`, если `release/`
  потребует прохождения строгих проверок, которые мы не потянем с первого
  раза — так меньше риск, что PR отклонят целиком.
- Найти требования к структуре папки одной клавиатуры (обычно
  `release/p/pontic_greek/` — по первой букве id) и к файлу метаданных
  `pontic_greek.keyboard_info` (у нас есть черновик в `keyman/build/
  keyman.keyboard_info` — свериться, что формат совпадает с актуальными
  требованиями репозитория, не факт что он не устарел).

### 2. Расширить поддержку платформ — ВАЖНО, это не сделано

Сейчас в `keyman/source/pontic_greek.kmn` стоит:
```
store(&TARGETS) 'mobile'
```
Это ограничивает клавиатуру телефонами и вебом. Для полноценного попадания
в каталог с поддержкой Windows/macOS/Linux нужно расширить targets (обычно
`desktop mobile web` или конкретный список — сверься с актуальным синтаксисом
Keyman Developer для `&TARGETS`). Проверить, что раскладка на десктопе не
конфликтует с уже существующими у нас нативными вариантами (AHK для Windows,
`.keylayout` для macOS) — это РАЗНЫЕ механизмы, они не должны спорить друг
с другом за одно и то же сочетание клавиш на одной машине. Если Keyman-версия
для десктопа неполноценна (например, набор мёртвых клавиш работает иначе,
чем в AHK) — лучше явно ограничить TARGETS только тем, что реально хорошо
работает, и не выдавать desktop как обещание, которое не выполняется.

### 3. Собрать пакет по требованиям репозитория

- Скорее всего понадобится `kmc` (Keyman Developer compiler, ставится как
  npm-модуль, см. Prerequisites в README) — собрать и прогнать локально
  `build.sh` / `kmc build`, чтобы убедиться, что наш `.kmn` компилируется
  их тулчейном без ошибок (не только нашим текущим процессом).
- Шрифт: если у репозитория есть общая папка `shared/fonts/` для шрифтов,
  используемых разными клавиатурами — проверить, нужно ли туда переносить
  PonticSans-Regular.ttf, или можно оставить встроенным в пакет клавиатуры
  как сейчас. См. раздел «Include font files» в README.
- Обновить лицензионные файлы, если формат/структура LICENSE отличается от
  требуемой (у нас OFL для шрифта, MIT для раскладки — уже готово в
  `font/OFL.txt`, но перепроверить, что именно требует их шаблон).

### 4. Локальная проверка перед PR

- Собрать клавиатуру их инструментом (`kmc build`) и убедиться, что нет
  предупреждений/ошибок компилятора.
- Проверить в Keyman Developer IDE (если доступен) или через их тестовый
  инструмент, что раскладка вводит все понтийские буквы: ξ̌ ζ̌ χ̌ ψ̌ σ̌ ς̌ κ̌
  Σ̌ Ξ̌ Ζ̌ Χ̌ Ψ̌ Κ̌ γ̆ Γ̆ α̤ ο̤ ά̤ ό̤ — полный список есть в главном README.md
  проекта (`ПИСЬМО_ДИ` файлы недоступны публично, туда не лезть).
- Убедиться, что welcome.htm корректно рендерится и описывает клавиатуру.

### 5. Pull Request

- Форкнуть `keymanapp/keyboards`, добавить нашу клавиатуру в нужную папку
  по их структуре, оформить commit по их конвенции (см. пример в README —
  `[id] updated keyboard` / `[id] new keyboard`).
- В описании PR указать: язык `pnt` (ISO 639-3, Pontic Greek), дополнительно
  `el` (Greek) как связанный язык, ссылку на наш проект-источник
  (https://github.com/msologr-cpu/pontic-greek) для контекста и истории.
- Быть готовым отвечать на ревью — у них есть автоматические проверки
  качества (lint/tests из `build.sh test`), скорее всего PR не пройдёт
  с первого раза, это нормально.

## Ограничения и что НЕ трогать

- Не менять существующий `keyman/build/pontic_greek.kmp` и не ломать текущий
  релиз v5.1, которым уже пользуются реальные люди — работать в отдельной
  ветке/форке, PR в наш репозиторий делать только после того, как локально
  всё подтверждено рабочим.
- Не публиковать никакие личные переписки, имена или контакты пользователей
  ни в PR, ни в commit-сообщениях, ни в описании клавиатуры — только
  технические данные (язык, платформы, лицензия).
- Если для прохождения `release/`-требований придётся сильно упрощать
  раскладку (терять функциональность гачека/бреве/точек снизу) — не делать
  тихо, сообщить и предложить варианты вместо самостоятельного решения.

подан PR / принят / что осталось, и оставить ссылку на PR.
