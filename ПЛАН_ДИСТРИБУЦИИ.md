# Пошаговый план дистрибуции понтийских шрифтов и клавиатур

Документ регламентирует порядок подачи шрифтов (v6.0) и раскладок в мировые инстанции стандартизации (Google, Apple, Microsoft, Unicode, Linux, Яндекс).

---

## 1. Ситуация с Keyman (что делаем прямо сейчас)

- **Что сейчас в Keyman:** В официальном репозитории `keymanapp/keyboards` смержен наш пакет `release/p/pontic_greek` (PR #4113). В него упакован ровно **один шрифт** — `PonticSans-Regular.ttf` версии 5.1.
- **Действие на период тестирования:** **Пока ничего не меняем.** Текущая версия 5.1 стабильно работает в каталоге Keyman и доступна пользователям по всему миру.
- **Действие после согласования v6.0:** Заменяем файл `keyman/source/PonticSans-Regular.ttf` на v6.0, поднимаем версию пакета до 6.0 в `pontic_greek.kps` и отправляем стандартный pull request на обновление в `keymanapp/keyboards`.

## 2. Очерёдность подачи в мировые инстанции

Инстанции выстроены по принципу: **от быстрых побед к фундаментальным системным стандартам**.

### Шаг 1. Внутреннее тестирование (Текущий этап)
- **Инструмент:** витрина `https://pontos.world/pontoskey/test.html`.
- **Цель:** Команда и филологи проверяют 8 начертаний v6.0 в разных кеглях, на macOS, Windows и смартфонах.
- **Критерий завершения:** Отмашка от команды «все символы сидят чисто».

### Шаг 2. Первая внешняя инстанция — Google Noto Fonts (Android / Google Docs)
- **Цель:** Устранить причину смещения гачеков в системном шрифте Android раз и навсегда.
- **Инстанция:** Репозиторий `googlefonts/noto-fonts` / `notofonts/latin-greek-cyrillic` (открытый тикет **Issue #547**).
- **Что подготовлено:** Документ `google_noto/issue_547_response.md` с точными координатами якорей OpenType GPOS для всех 15 верхних и 13 нижних целевых знаков.
- **Действие:** Публикация ответа в Issue #547 и оформление Pull Request с якорными точками в upstream репозиторий Noto.
- **Результат:** Google вливает наши координаты в Noto Sans и Noto Serif. С очередным обновлением Android понтийская диакритика начинает отображаться на всех телефонах мира без установки сторонних шрифтов.

### Шаг 4. Главная фундаментальная инстанция — Unicode CLDR (unicode.org)

По правилам приёма раскладок в CLDR (Keyboard Repository Process) все локали, указанные в клавиатуре, должны обязательно существовать в CLDR **минимум на уровне Core Data**. Процесс строго разделён на два последовательных подшага.

#### Шаг 4a. Доведение локали pnt до уровня Core Data в CLDR
- **Результаты проверки ветки main в `unicode-org/cldr`:**
  - `common/main/pnt.xml` — **ОТСУТСТВУЕТ** (404).
  - `common/supplemental/likelySubtags.xml` — **ПРИСУТСТВУЕТ**: `<likelySubtag from="pnt" to="pnt_Grek_GR"/>`, а также связки для RU (`pnt_Cyrl_RU`) и TR (`pnt_Latn_TR`).
  - `common/supplemental/supplementalData.xml` — **ПРИСУТСТВУЕТ**: `languageData` для `pnt` (`scripts="Grek"`), и демография для территорий `GR` (3.7%), `RU` (0.04%), `TR` (0.0061%).
  - `common/validity/language.xml` — **ПРИСУТСТВУЕТ** в валидном регулярном диапазоне `png~z` (на базе IANA Subtag с 2009 г.).
  - `common/supplemental/supplementalMetadata.xml` (`defaultContent`) — **ОТСУТСТВУЕТ**.
  - `common/supplemental/attributeValueValidity.xml` (`$languageNonTcLtBasic`) — **ОТСУТСТВУЕТ**.
  - Открытые PR на GitHub и тикеты в Unicode Jira (проект CLDR) по Pontic / pnt — **ОТСУТСТВУЮТ**.
  - **Вывод проверки:** Язык частично описан в метаданных, но самой локали на уровне Core Data в CLDR **НЕТ**. Подавать клавиатуру без Core Data нельзя.
- **Что подготовлено (каталог `cldr/core_proposal/`):**
  1. `pnt.xml` — основной файл локали с наборами символов (exemplars: основной, политонический auxiliary, index, numbers, punctuation).
  2. `pnt_GR.xml` — региональный файл локали для территории по умолчанию.
  3. `patch_attributeValueValidity.diff` — добавление `pnt` в список языков.
  4. `patch_supplementalMetadata.diff` — добавление `pnt_GR` в `defaultContent`.
  5. `CLDR_CORE_LOCALE_SUBMISSION.md` — полный текст заявки для Unicode Jira.
- **Статус 4a:** Готов черновик пакета Core Data. **Требуется подтверждение Макса** по выбору региона по умолчанию (`GR`) и оценке численности перед отправкой в Jira. До согласия ничего во внешние сервисы не отправляется.

#### Шаг 4b. Подача раскладки клавиатуры в CLDR Keyboard Subproject
- **Условие старта:** Запускается **СТРОГО ПОСЛЕ** закрытия шага 4a (принятия Core Data локали `pnt`).
- **Требования к раскладке:**
  - Соответствие стандарту CLDR Keyboard Format 3.0 (UTS #35 Part 7).
  - Запрещены теги `<forms>`, `<special>` и пользовательские namespace.
  - Локаль минимизирована (`locale="pnt"` согласно likelySubtags).
  - Статус подачи: `proposed`.
- **Что подготовлено:** Файл `cldr/pnt.xml` (полностью чистый, проверен на отсутствие `<forms>` и `<special>`).
- **Результат:** После принятия в CLDR раскладка попадает во все операционные системы (iOS, macOS, Windows, Android Gboard) как стандартная системная клавиатура.

---

### Шаг 5. Linux freedesktop.org (`xkeyboard-config`)
- **Цель:** Нативная раскладка во всех дистрибутивах Linux (Ubuntu, Debian, Fedora, Arch).
- **Инстанция:** GitLab проект `xkeyboard-config` на freedesktop.org.
- **Что подготовлено:** Файл символов `symbols/pnt`.
- **Действие:** Merge Request в ветку `master` проекта `xkeyboard-config`.
- **Результат:** Выбор понтийского языка в настройках ввода Linux прямо из системного меню.

---

### Шаг 6. Яндекс Клавиатура (РФ и СНГ)
- **Цель:** Добавление понтийского языка в популярную мобильную клавиатуру «Яндекс Клавиатура» (iOS / Android).
- **Инстанция:** Команда мобильного ввода Яндекс (Yandex Mobile Keyboard Team).
- **Что готовим:**
  1. Спецификацию раскладки (на базе `pnt-3-rows.yaml` и `pnt-longpress.yaml`).
  2. Частотный словарь лемм (на базе оцифрованного нами корпуса словаря Пападопулоса).
- **Действие:** Официальное обращение в команду разработки Яндекс Клавиатуры с готовым языковым пакетом.
